一次请求的完整路径

应用层发起 /v1/chat/completions → 接口协议层鉴权并规范化请求 → 统一调度层按模型名路由到合适的运行时实例并排队 → 计算引擎层把权重从模型存储层 （GGUF / safetensors / ONNX）加载到显存或内存 → 硬件接口层通过 CUDA / ROCm / SYCL / Vulkan / Metal 下发算子 → Token 逐个返回，全程由可观测性组件采集指标。

选型提示

同一模型常有多条推理路径：llama.cpp 适合 CPU 与边缘设备，vLLM / SGLang 适合 GPU 上的高吞吐服务， MLX 面向 Apple Silicon。Xinference 与 LocalAI 会依据模型格式（GGUF / PyTorch / GPTQ / AWQ / FP8） 自动选择后端，也可通过配置文件显式指定。
